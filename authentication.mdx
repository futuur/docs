Every request to the Futuur API must be authenticated. Authentication uses HMAC-SHA512 signatures generated from your public/private key pair. There are no bearer tokens or session cookies — each request is independently signed.

## Get your API keys

Get a public/private HMAC pair from **Settings** → **API keys**, or derive the same pair by signing with your wallet (phase-one preview host only). Full steps and the wallet-derive payload are in [Get your API keys](/guides/get-api-keys).

- **Public key** — included in every request as the `Key` header. Safe to log.
- **Private key** — used to sign requests. Never share or log this value.

<Note>
  On the phase-one preview host, HMAC authenticates the HTTP request and nothing else. Every order in `OOM` or `USDC` also needs an EIP-712 `LimitOrderIntent` signed by your Safe owner key. HMAC never replaces that wallet signature. See [Environment](/environment) and [On-chain trading](/concepts/on-chain-trading).
</Note>

## Required headers

Every authenticated request must include these three headers:

| Header | Value |
|--------|-------|
| `Key` | Your public key |
| `Timestamp` | Current Unix timestamp in seconds (UTC epoch, for example `int(time.time())`) |
| `HMAC` | SHA-512 hexdigest of the signed parameter string |

## Signing process

The server rebuilds one string from your request and compares its HMAC-SHA512 with your `HMAC` header. The method and the path are **not** signed. Only the parameters, `Key`, and `Timestamp` are.

<Steps>
  <Step title="Collect the parameters">
    Start with the top-level fields of the request body (a JSON object or form fields). Add the query string parameters; on a duplicate name the query string value wins. Then add `Key` (your public key) and `Timestamp` (the exact string you send in the header). A request with no body and no query string signs only `Key` and `Timestamp`.
  </Step>
  <Step title="Sort by name (case-sensitive)">
    Sort by parameter name in **code-point order**, the order Python's `sorted()` produces. Uppercase letters sort before lowercase, so `Key` and `Timestamp` come before `category`. A case-insensitive or locale-aware comparator (for example JavaScript `localeCompare`) produces a different string.
  </Step>
  <Step title="Encode exactly like Python urlencode">
    Join the pairs as `name=value&name=value`. Convert each name and value to text, then percent-encode it with the rules of Python `urllib.parse.urlencode` (`quote_plus`):

    - Letters, digits, and `_ . - ~` stay as they are.
    - A space becomes `+`, not `%20`.
    - Every other character becomes `%XX` for each of its UTF-8 bytes, with uppercase hex. That includes `! ' ( ) *`, which JavaScript `encodeURIComponent` leaves unescaped.

    ```
    Key=YOUR_PUBLIC_KEY&Timestamp=1712500000&category=5
    ```
  </Step>
  <Step title="Sign with your private key">
    Compute an HMAC-SHA512 digest using your private key as the secret and the string as the message. Send the hex digest (not base64) in the `HMAC` header.
  </Step>
</Steps>

### How values become text

The server signs what it **parsed**, not the bytes you sent. For a JSON body, each top-level value is converted with Python `str()`:

| JSON value | Signed as |
|---|---|
| `"0.42"` (string) | `0.42` |
| `3` (integer) | `3` |
| `0.50` (number) | `0.5` — the parsed float, not your literal |
| `true` / `false` | `True` / `False` |
| `null` | `None` |
| Object or array | Its Python `repr`. `{"a": 1, "b": [true, "x"]}` is signed as `{'a': 1, 'b': [True, 'x']}` before percent-encoding |

Form-encoded bodies and query strings are always strings and are signed exactly as sent. If a name repeats, the last value is signed.

<Tip>
  Send a form-encoded body, or a JSON body whose values are all strings (`"price": "0.42"`, `"shares": "3"`, `"chain_id": "84532"`). Then the signed text is the text you sent, in any language. Numeric, decimal, and boolean fields accept strings. Sign nested objects or arrays only from Python, where `str()` gives the server's form. The endpoints with nested bodies are `POST /orders/batch/`, `POST /orders/batch-update/`, `POST /orders/batch-cancel/`, and the Safe relay endpoints.
</Tip>

### Timestamp window

`Timestamp` must be an integer Unix time in seconds, within **300 seconds** of the server clock in either direction. Keep your clock synchronized (NTP) and sign every request fresh.

## Code examples

<CodeGroup>

```python python
import hashlib
import hmac
import time
from urllib.parse import urlencode

import requests

BASE = "https://api.futuur.com/v2.0"
PUBLIC_KEY = "your_public_key"
PRIVATE_KEY = "your_private_key"


def sign(params: dict) -> dict:
    """Return the three auth headers for a request with these parameters.

    `params` holds the query parameters of a GET, or the top-level body
    fields of a POST/PATCH, with the same values you send.
    """
    timestamp = str(int(time.time()))
    to_sign = {**params, "Key": PUBLIC_KEY, "Timestamp": timestamp}
    message = urlencode(sorted(to_sign.items()))
    digest = hmac.new(PRIVATE_KEY.encode(), message.encode(), hashlib.sha512).hexdigest()
    return {"Key": PUBLIC_KEY, "Timestamp": timestamp, "HMAC": digest}


# GET with query parameters
query = {"category": "5"}
response = requests.get(f"{BASE}/events/", params=query, headers=sign(query))

# POST with a JSON body whose values are all strings
body = {"market": "3801"}
response = requests.post(f"{BASE}/orders/cancel-all/", json=body, headers=sign(body))
```

```javascript javascript
const crypto = require("crypto");

const BASE = "https://api.futuur.com/v2.0";
const PUBLIC_KEY = "your_public_key";
const PRIVATE_KEY = "your_private_key";

// Python quote_plus: space becomes "+", and ! ' ( ) * are escaped.
function quotePlus(text) {
  return encodeURIComponent(text)
    .replace(/[!'()*]/g, (c) => "%" + c.charCodeAt(0).toString(16).toUpperCase())
    .replace(/%20/g, "+");
}

// The text the server signs for a top-level value.
function pyStr(value) {
  if (typeof value === "string") return value;
  if (typeof value === "boolean") return value ? "True" : "False";
  if (value === null) return "None";
  if (Number.isSafeInteger(value)) return String(value);
  throw new Error("Send decimals as strings and do not sign nested values");
}

function sign(params = {}) {
  const timestamp = String(Math.floor(Date.now() / 1000));
  const toSign = { ...params, Key: PUBLIC_KEY, Timestamp: timestamp };
  const message = Object.keys(toSign)
    .sort() // code-unit order. Never localeCompare.
    .map((k) => `${quotePlus(k)}=${quotePlus(pyStr(toSign[k]))}`)
    .join("&");
  const digest = crypto.createHmac("sha512", PRIVATE_KEY).update(message).digest("hex");
  return { Key: PUBLIC_KEY, Timestamp: timestamp, HMAC: digest };
}

// GET with query parameters
const query = { category: "5" };
fetch(`${BASE}/events/?${new URLSearchParams(query)}`, { headers: sign(query) })
  .then((res) => res.json())
  .then(console.log);

// POST with a form-encoded body: the signed values are the strings you send
function post(path, fields) {
  return fetch(`${BASE}${path}`, {
    method: "POST",
    headers: { ...sign(fields), "Content-Type": "application/x-www-form-urlencoded" },
    body: new URLSearchParams(fields),
  });
}

post("/orders/cancel-all/", { market: "3801" });
```

```bash curl
curl "https://api.futuur.com/v2.0/events/?category=5" \

```

## GET vs. POST requests

- **GET requests**: sign the query string parameters plus `Key` and `Timestamp`.
- **POST and PATCH requests**: sign the top-level body fields plus `Key` and `Timestamp`. If you also send a query string, those parameters are signed too, and they override body fields of the same name.

<Tip>
  If your request has no parameters (for example `GET /me/` or `PATCH /orders/{id}/cancel/`), you still sign just `Key` and `Timestamp`.
</Tip>

## Errors

Every HMAC failure returns the same status and code. The API does not tell you which check failed.

```json 401 Unauthorized
{
  "type": "client_error",
  "errors": [
    {
      "code": "authentication_failed",
      "detail": "Incorrect authentication credentials.",
      "attr": null
    }
  ]
}
```

| Cause | What to check |
|-------|---------------|
| Unknown or deactivated public key | The `Key` header. Creating a new pair in **Settings** deactivates the old one. |
| Signature mismatch | Sort order, `+` for spaces, `True` / `False` / `None`, a number the server parsed differently from your literal, a parameter you sent but did not sign, or the wrong private key. |
| `Timestamp` missing or not an integer | Send Unix seconds as digits. `detail` reads `Invalid or missing request timestamp.` |
| `Timestamp` more than 300 seconds off | Synchronize your clock. `detail` reads `Request timestamp is outside the allowed window.` |

Two cases look different:

- If the `HMAC` or `Key` header is missing, the request is treated as unauthenticated. Protected endpoints answer `401` with code `not_authenticated`.
- After 300 failed HMAC attempts within a minute from one IP address, further attempts get `429` with code `throttled` until the minute ends.

See [Errors](/errors) for the response format and the full list of codes.

<Warning>
  Never include your private key in client-side code or commit it to version control. Treat it with the same care as a password.
</Warning>
