---

This guide walks you through finding an event, checking the current price, and placing an order — from an immediate order that takes the best prices to a limit order that rests on the book.

<Note>
  All examples use `https://api.futuur.com/v2.0`. Authenticated requests require HMAC headers. See [Get your API keys](/guides/get-api-keys) and the [Authentication](/authentication) guide for how to generate them.
</Note>

<Note>
  On the phase-one preview host, orders in `OOM` and `USDC` also need the signed-intent fields (`order_intent_signature`, `order_intent_expiry`, `order_intent_nonce`, `max_usdc_raw`). The bodies below show the order fields only. See [Place an on-chain order](/guides/on-chain-first-order) and [Environment](/environment).
</Note>

<Steps>

<Step title="Find an event">

Use `GET /v2.0/events/` to browse available prediction markets. You can search by keyword or filter by category. This endpoint does not require authentication.

<CodeGroup>

```python python
import requests

response = requests.get(
    "https://api.futuur.com/v2.0/events/",
    params={
        "search": "US election",
        "currency_mode": "play_money",
        "limit": 5,
    },
)

events = response.json()["results"]
for event in events:
    print(event["id"], event["title"])
```

```bash curl
curl -G "https://api.futuur.com/v2.0/events/" \
  --data-urlencode "search=US election" \
  --data-urlencode "currency_mode=play_money" \
  --data-urlencode "limit=5"
```

</CodeGroup>

The response includes a `results` array of events. Each event has an `id` and a `markets` array containing individual outcomes you can bet on.

<Tip>
  Set `currency_mode=play_money` while testing. Switch to `real_money` when you're ready to trade with USDC, USDT, or USD.
</Tip>

</Step>

<Step title="Inspect the event's markets">

Each event has one or more markets, each representing a possible outcome. Retrieve a single event to see its markets in detail.

<CodeGroup>

```python python
response = requests.get(
    "https://api.futuur.com/v2.0/events/12345/",
    headers={
        "Key": "YOUR_PUBLIC_KEY",
        "Timestamp": "1712500000",
        "HMAC": "YOUR_HMAC_SIGNATURE",
    },
)

event = response.json()
print(f"Event: {event['title']}")
for market in event["markets"]:
    print(f"  Market {market['id']}: {market['title']} @ {market['price']}")
```

```bash curl
curl "https://api.futuur.com/v2.0/events/12345/" \
  -H "Key: YOUR_PUBLIC_KEY" \
  -H "Timestamp: 1712500000" \
  -H "HMAC: YOUR_HMAC_SIGNATURE"
```

</CodeGroup>

Note the `id` of the market you want to bet on and its current `price` (implied probability between 0 and 1).

</Step>

<Step title="Place an immediate order">

To buy shares right away, send `time_in_force: "ioc"` with the highest `price` you accept. The order fills at that price or better, and any unfilled remainder is canceled.

A market order (`price: null`) cannot be used for `OOM` or `USDC` on the phase-one preview host, because the signed intent contains a price.

<CodeGroup>

```python python
response = requests.post(
    "https://api.futuur.com/v2.0/orders/",
    headers={
        "Key": "YOUR_PUBLIC_KEY",
        "Timestamp": "1712500000",
        "HMAC": "YOUR_HMAC_SIGNATURE",
        "Content-Type": "application/json",
    },
    json={
        "market": "67890",
        "side": "bid",
        "position": "long",
        "shares": "100",
        "currency": "OOM",
        "price": "0.47",
        "time_in_force": "ioc",
    },
)

print(response.json())
```

```bash curl
curl -X POST "https://api.futuur.com/v2.0/orders/" \
  -H "Key: YOUR_PUBLIC_KEY" \
  -H "Timestamp: 1712500000" \
  -H "HMAC: YOUR_HMAC_SIGNATURE" \
  -H "Content-Type: application/json" \
  -d '{
    "market": "67890",
    "side": "bid",
    "position": "long",
    "shares": "100",
    "currency": "OOM",
    "price": "0.47",
    "time_in_force": "ioc"
  }'
```

</CodeGroup>

</Step>

<Step title="Place a limit order">

To rest on the book at your own price, send a `price` between `0.01` and `0.99` and leave `time_in_force` at its default (`gtc`). The order fills when someone trades against it.

<CodeGroup>

```python python
response = requests.post(
    "https://api.futuur.com/v2.0/orders/",
    headers={
        "Key": "YOUR_PUBLIC_KEY",
        "Timestamp": "1712500000",
        "HMAC": "YOUR_HMAC_SIGNATURE",
        "Content-Type": "application/json",
    },
    json={
        "market": "67890",
        "side": "bid",
        "position": "long",
        "shares": "100",
        "currency": "OOM",
        "price": "0.45",
    },
)

print(response.json())
```

```bash curl
curl -X POST "https://api.futuur.com/v2.0/orders/" \
  -H "Key: YOUR_PUBLIC_KEY" \
  -H "Timestamp: 1712500000" \
  -H "HMAC: YOUR_HMAC_SIGNATURE" \
  -H "Content-Type: application/json" \
  -d '{
    "market": "67890",
    "side": "bid",
    "position": "long",
    "shares": "100",
    "currency": "OOM",
    "price": "0.45"
  }'
```

</CodeGroup>

If the best ask is above 0.45, your order rests on the book until someone sells at that price. The response shows `status: "processing"` first; the order becomes `open` once matching has run. See [Order lifecycle](/concepts/orders#order-lifecycle).

</Step>

</Steps>
