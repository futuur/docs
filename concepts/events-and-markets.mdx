An **event** is a prediction question that you can bet on — for example, "Who will win the 2024 US Presidential Election?" or "Will Bitcoin exceed $100,000 by end of year?" Each event has one or more **markets**, which are the outcomes you can trade.

<Note>
  The API uses the term `markets` for what were previously called "Outcomes" in older versions of the API. Events were previously called "Questions."
</Note>

## Events

An event defines the question, the resolution criteria, and the timeframe. Key fields on an event object include:

| Field | Description |
|---|---|
| `id` | Unique identifier |
| `title` | The prediction question |
| `slug` | URL-friendly identifier |
| `status` | Current state: `open`, `stopped`, `resolved`, `cancelled`, `paused`, or `reversed` |
| `category` | Array of category objects the event belongs to |
| `markets` | Array of outcome markets |
| `bet_end_date` | When betting closes |
| `resolve_date` | When the event was resolved |
| `markets_correlation` | How markets relate to each other (see below) |
| `description` | Full question details and resolution criteria |

### Event statuses

<AccordionGroup>
  <Accordion title="open">
    The event is active and accepting bets. You can place, modify, and cancel orders.
  </Accordion>
  <Accordion title="stopped">
    Trading has stopped — `bet_end_date` has passed — but the event has not yet resolved. No new orders are accepted.
  </Accordion>
  <Accordion title="resolved">
    The outcome has been determined. Winning wagers are paid out and losing wagers are settled. The event is read-only.
  </Accordion>
  <Accordion title="cancelled">
    The event was cancelled and will not resolve normally.
  </Accordion>
  <Accordion title="paused">
    Trading is temporarily paused on this event.
  </Accordion>
  <Accordion title="reversed">
    A previous resolution was reversed.
  </Accordion>
</AccordionGroup>

## Markets

A **market** represents a possible outcome within an event. For a binary event like "Will X happen?", there are two markets: Yes and No. For a multi-outcome event like "Who will win?", each candidate is a separate market.

Key fields on a market object include:

| Field | Description |
|---|---|
| `id` | Unique identifier |
| `name` | The outcome name (e.g., "Yes", "Candidate A") |
| `price` | Current market price (probability) between 0 and 1 |
| `liquidity_play_money` | Total shares resting in open orders at every price (play money) |
| `liquidity_real_money` | Total shares resting in open orders at every price (real money) |
| `depth_play_money` | Shares in open orders priced from 0.45 to 0.55 (play money) |
| `depth_real_money` | Shares in open orders priced from 0.45 to 0.55 (real money) |

## Markets correlation

The `markets_correlation` field on an event determines how prices are calculated and how bets impact market dynamics:

<AccordionGroup>
  <Accordion title="Linked prices (default)">
    Markets are correlated. The sum of all market prices equals 1, and placing a bet on one market automatically affects the prices of other markets in the same event. This is the default correlation type for most events.
  </Accordion>
  <Accordion title="Independent">
    Markets operate independently. Each market's price is calculated separately, and betting on one market does not affect others. Use this for events where outcomes are not mutually exclusive.
  </Accordion>
</AccordionGroup>

## Long and short positions

When you trade a market, you take either a **long** or **short** position:

- **Long** — You believe this outcome will happen. You profit if the market resolves Yes.
- **Short** — You believe this outcome will not happen. You profit if the market resolves No.

For binary events, going long on Yes is equivalent to going short on No.

## Listing events

Use `GET /v2.0/events/` to list available prediction markets. The endpoint supports filtering by:

| Parameter | Description |
|---|---|
| `categories` | Comma-separated category IDs. A root category includes its descendants. |
| `category_slug` | Comma-separated category slugs as an alternative to IDs. |
| `search` | Case-insensitive search across title, market names, categories, and tags. |
| `tag` | Comma-separated tag slugs or names (up to 10). |
| `currency_mode` | `play_money` or `real_money`. Defaults to `play_money`. |
| `live` | When true, return events that are live now or start within 12 hours. |
| `resolved_only` | When true, return only resolved events. |
| `pending_resolution` | When true, return unresolved events whose close time has passed. |
| `bet_end_date_after` | Inclusive lower bound for `bet_end_date` (ISO 8601 with timezone). |
| `bet_end_date_before` | Inclusive upper bound for `bet_end_date` (ISO 8601 with timezone). |
| `hide_my_bets` | Authenticated only. Omit events the user has already bet on. |
| `only_markets_i_follow` | Authenticated only. Return events the user follows. |

### Ordering

Use the `ordering` parameter to sort results. Allowed values:

- `relevance`, `-relevance`
- `created_on`, `-created_on`
- `bet_end_date`, `-bet_end_date`
- `wagers_count`, `-wagers_count`
- `volume`, `-volume`
- `open_date`, `-open_date`
- `resolve_date`, `-resolve_date`

Prefix with `-` for descending order.

## Example: Fetching events

```bash
curl -G "https://api.futuur.com/v2.0/events/" \
  --data-urlencode "search=election" \
  --data-urlencode "currency_mode=play_money" \
  --data-urlencode "limit=10" \
  --data-urlencode "ordering=-volume"
```

This returns up to 10 play-money events matching "election", ordered by highest volume first.
