An **event** is a prediction question that you can bet on — for example, "Who will win the 2024 US Presidential Election?" or "Will Bitcoin exceed $100,000 by end of year?" Each event has one or more **markets**, which are the outcomes you can trade.

<Note>
  The API uses the term `markets` for what were previously called "Outcomes" in older versions of the API. Events were previously called "Questions."
</Note>

## Events

An event defines the question, the resolution criteria, and the timeframe. Key fields on an event object include:

| Field | Description |
|---|---|
| `id` | Unique identifier |
| `title` | The prediction question |
| `slug` | URL-friendly identifier |
| `status` | Current state: `open`, `stopped`, `resolved`, `cancelled`, `paused`, or `reversed` |
| `category` | Array of category objects the event belongs to |
| `markets` | Array of outcome markets |
| `bet_end_date` | When betting closes |
| `resolve_date` | When the event was resolved |
| `markets_correlation` | How markets relate to each other (see below) |
| `description` | Full question details and resolution criteria |

### Event statuses

<AccordionGroup>
  <Accordion title="open">
    The event is active and accepting bets. You can place, modify, and cancel orders.
  </Accordion>
  <Accordion title="stopped">
    Trading has stopped — `bet_end_date` has passed — but the event has not yet resolved. No new orders are accepted.
  </Accordion>
  <Accordion title="resolved">
    The outcome has been determined. Winning wagers are paid out and losing wagers are settled. The event is read-only.
  </Accordion>
  <Accordion title="cancelled">
    The event was cancelled and will not resolve normally.
  </Accordion>
  <Accordion title="paused">
    Trading is temporarily paused on this event.
  </Accordion>
  <Accordion title="reversed">
    A previous resolution was reversed.
  </Accordion>
</AccordionGroup>

## Markets

Each market represents one possible outcome within an event. Markets have their own prices, order books, and liquidity.

### Markets correlation

The relationship between markets in an event is defined by **markets correlation**:

| Correlation | Description |
|---|---|
| **Linked prices** | Markets are correlated. The sum of all market prices equals 1, and placing a bet on one market automatically affects the prices of other markets in the same event. This is the default correlation type. |
| **Independent** | Markets operate independently. Each market's price is calculated separately, and betting on one market does not affect others. |

The correlation type determines how prices are calculated and how bets impact market dynamics within an event.

## Liquidity, depth, and the order book

These are three different measures of size. All three count **shares**, not currency.

| Field | Description |
|---|---|
| `liquidity_play_money` / `liquidity_real_money` | Sum of shares resting in open orders at every price. The suffix selects the currency mode. |
| `depth_play_money` / `depth_real_money` | Same sum, but restricted to orders priced from 0.45 to 0.55. |

The order book lists each price on its own. `GET /v2.0/markets/{id}/book/` returns:

| Field | Description |
|---|---|
| `total_shares` | Size resting at that price |
| `cumulative_shares` | Running total in execution order: asks from the lowest price, bids from the highest |
| `last_price` | Price of the latest trade |
| `last_trade_at` | Timestamp of the latest trade |
| `last_trade_taker_side` | Side of the taker in the latest trade |
| `volume_24h` | Rolling 24-hour volume |
| `trades_24h` | Rolling 24-hour trade count |

<Tip>
  For live updates, use the WebSocket gateway. `best-prices-change` pushes the best bid and ask. `order-book-update` pushes the top 5 levels of one market, with `total_shares` at each price.
</Tip>

## Positions: long and short

When you trade a market, you take a **position**:

- **Long** — you believe this outcome will happen. You profit if the market price rises or the outcome resolves as correct.
- **Short** — you believe this outcome will not happen. You profit if the market price falls or the outcome resolves as incorrect.

## Fetching events

Use `GET /v2.0/events/` to list events. You can filter by:

| Parameter | Description |
|---|---|
| `search` | Case-insensitive search across title, market names, categories, and tags |
| `categories` | Comma-separated category IDs. A root category includes its descendants |
| `category_slug` | Comma-separated category slugs as an alternative to `categories` |
| `tag` | Comma-separated tag slugs or names (up to 10) |
| `currency_mode` | `play_money` or `real_money` (defaults to `play_money`) |
| `live` | When true, return events that are live now or start within 12 hours |
| `resolved_only` | When true, return only resolved events |
| `pending_resolution` | When true, return unresolved events whose close time has passed |
| `bet_end_date_after` | Inclusive lower bound for `bet_end_date` (ISO 8601 with timezone) |
| `bet_end_date_before` | Inclusive upper bound for `bet_end_date` (ISO 8601 with timezone) |
| `hide_my_bets` | Authenticated only. Omit events the user has already bet on |
| `only_markets_i_follow` | Authenticated only. Return events the user follows |

### Ordering results

Use the `ordering` parameter to sort events:

| Value | Description |
|---|---|
| `relevance` / `-relevance` | Sort by relevance (default for search) |
| `created_on` / `-created_on` | Sort by creation date |
| `bet_end_date` / `-bet_end_date` | Sort by betting end date |
| `wagers_count` / `-wagers_count` | Sort by number of wagers |
| `volume` / `-volume` | Sort by trading volume |
| `open_date` / `-open_date` | Sort by open date |
| `resolve_date` / `-resolve_date` | Sort by resolution date |

Prefix with `-` for descending order.
