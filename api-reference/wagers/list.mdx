---
title: 'List wagers'
description: 'Retrieve a paginated list of wagers, with optional filters by user, event, activity status, and currency mode.'
---

Retrieve a list of wagers. You can filter by active status, event, currency mode, or by bets placed by users you follow. Authenticated requests return your own wagers by default. Public wagers can also be accessed without authentication.

## Endpoint

```
GET https://api.futuur.com/v2.0/wagers/
```

## Authentication

<Note>
  Authentication is optional for this endpoint. Unauthenticated requests can access public wager data. To access your own private wagers or filter by followed users, include the `Key`, `Timestamp`, and `HMAC` headers.
</Note>

## Request

<ParamField query="active" type="boolean">
  When `true`, returns only active wagers with a status of `purchased`.
</ParamField>

<ParamField query="past_bets" type="boolean">
  When `true`, returns only inactive wagers — those that are sold, won, lost, cancelled, or disabled.
</ParamField>

<ParamField query="event" type="integer">
  Filter wagers by event ID.
</ParamField>

<ParamField query="user" type="integer">
  Filter wagers by user ID.
</ParamField>

<ParamField query="following" type="boolean">
  When `true`, returns only wagers placed by users you follow.
</ParamField>

<ParamField query="currency_mode" type="string">
  Filter by currency mode: `play_money`, `real_money`, or an empty string to return all.
</ParamField>

<ParamField query="limit" type="integer">
  Number of results to return per page.
</ParamField>

<ParamField query="offset" type="integer">
  Pagination offset. Number of results to skip before returning results.
</ParamField>

## Response

Returns a paginated list of wager objects.

<ResponseField name="count" type="integer" required>
  Total number of wagers matching the query.
</ResponseField>

<ResponseField name="next" type="string">
  URL to the next page of results, or `null` if there are no more pages.
</ResponseField>

<ResponseField name="previous" type="string">
  URL to the previous page of results, or `null` if on the first page.
</ResponseField>

<ResponseField name="results" type="array" required>
  Array of wager objects.
  <Expandable title="Wager object properties">
    <ResponseField name="id" type="integer" required>
      Unique wager ID.
    </ResponseField>
    <ResponseField name="status" type="string" required>
      Wager status: `purchased`, `sold`, `won`, `lost`, `cancelled`, or `disabled`.
    </ResponseField>
    <ResponseField name="status_display" type="string" required>
      Human-readable status label.
    </ResponseField>
    <ResponseField name="user" type="string" required>
      User resource reference (read-only).
    </ResponseField>
    <ResponseField name="event" type="string" required>
      Event resource reference (read-only).
    </ResponseField>
    <ResponseField name="market" type="string" required>
      Market resource reference (read-only).
    </ResponseField>
    <ResponseField name="position" type="string" required>
      Position direction: `long` (in favor of the outcome) or `short` (against).
    </ResponseField>
    <ResponseField name="position_display" type="string" required>
      Human-readable position label.
    </ResponseField>
    <ResponseField name="currency" type="string">
      Currency code for the wager (for example `OOM`, `USDC`).
    </ResponseField>
    <ResponseField name="shares" type="number" required>
      Consolidated shares held in this wager.
    </ResponseField>
    <ResponseField name="active_purchases" type="array">
      The purchases that make up the open position, oldest first. Each entry has `action`, `shares`, `price`, `amount`, `currency`, and `created`. This list is capped. See [Active purchases are capped](#active-purchases-are-capped).
    </ResponseField>
    <ResponseField name="active_purchases_amount" type="string">
      Amount from all active purchases on this wager, not only the ones listed in `active_purchases`.
    </ResponseField>
    <ResponseField name="purchases_amount" type="number">
      Cost basis of the open position. It covers every purchase, not only the ones listed in `active_purchases`.
    </ResponseField>
  </Expandable>
</ResponseField>

## Active purchases are capped

In this list, `active_purchases` holds at most 20 entries per wager: the 20 newest purchases, still oldest first. A position built from many small purchases has more than that, and the rest are left out of the list response.

- The cap applies to each wager in `results`, on every request to this endpoint, whatever filters you send.
- It applies to the `active_purchases` array only. Wagers themselves are not capped, and `limit` and `offset` page through wagers, not through purchases. Paging does not return the older purchases.
- `shares`, `active_purchases_amount`, and `purchases_amount` still cover every purchase.
- To read all active purchases of one wager, call [`GET /wagers/{id}/`](/api-reference/wagers/retrieve). It returns the full list.

## Example

```bash cURL
curl --request GET \
  --url "https://api.futuur.com/v2.0/wagers/?active=true&currency_mode=play_money" \
  --header "Key: YOUR_PUBLIC_KEY" \
  --header "Timestamp: 1712500000" \
  --header "HMAC: YOUR_HMAC_SIGNATURE"
```
