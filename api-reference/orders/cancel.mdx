---
title: 'Cancel order'
description: 'Cancel an open limit order by its ID.'
---

Cancel an open limit order. Only an order with status `open` can be canceled, including a `gtc` order that is partly filled (it stays `open`). Canceling stops the unfilled remainder; shares already filled stay filled. Canceling needs HMAC only, not a wallet signature.

## Endpoint

```
PATCH https://api.futuur.com/v2.0/orders/{id}/cancel/
```

## Authentication

<Note>
  This endpoint requires HMAC authentication. Include the `Key`, `Timestamp`, and `HMAC` headers on every request. See the [authentication guide](/authentication) for signing instructions.
</Note>

## Request

<ParamField path="id" type="integer" required>
  The ID of the limit order to cancel.
</ParamField>

This endpoint does not accept a request body.

## Response

Returns `204 No Content` on success. No response body is returned.

Otherwise:

| Order | Response |
| --- | --- |
| `processing` (being matched or settling) | `403` with code `LimitOrderBeingProcessing`. Retry shortly. |
| `filled`, `partial_filled`, `partial_filled_cancelled`, or `canceled` | `404` with code `not_found`. |
| Not yours, or does not exist | `404` with code `not_found`. |
| On an event that is no longer open | `404` with code `not_found`. |

<Warning>
  A `404` does not tell you whether the order filled or was canceled. Read its final state from [List orders](/api-reference/orders/list) with the matching `status` filter.
</Warning>

## Example

<CodeGroup>

```bash cURL
curl --request PATCH \
  --url "https://api.futuur.com/v2.0/orders/10482/cancel/" \
  --header "Key: YOUR_PUBLIC_KEY" \
  --header "Timestamp: 1712534400" \
  --header "HMAC: YOUR_HMAC_SIGNATURE"
```

</CodeGroup>

```
HTTP/1.1 204 No Content
```
